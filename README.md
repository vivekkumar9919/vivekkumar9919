## 🧩 Code Style & Engineering Principles

> *"Good code solves today's problem. Good design makes tomorrow's changes easier."*

- 🧱 **Separation of Concerns** — Keep business logic independent of infrastructure wherever practical.
- 🧰 **Modular by Design** — Prefer focused components with clear responsibilities and boundaries.
- 🔁 **Idempotency & Resilience** — Design retries and asynchronous workflows with duplicate processing and partial failures in mind.
- ⚙️ **Configuration over Hardcoding** — Build reusable, configurable integrations instead of repeating platform-specific logic.
- 🧪 **Test the Failure Paths** — Cover edge cases, unexpected responses, timeouts, and recovery scenarios.
- 📐 **Pragmatic Architecture** — Avoid unnecessary abstraction; optimize for clarity, maintainability, and actual requirements.

## 🔍 Debugging Is My Superpower

> *"Logs tell stories. Traces connect the chapters. Metrics reveal the plot."*

I enjoy investigating issues that aren't obvious from the code alone.

- 🔎 Trace failures across services using structured logs and correlation IDs.
- 📊 Use metrics and monitoring to identify bottlenecks and unusual behavior.
- 🧵 Investigate queue backlogs, consumer lag, retry loops, and stalled processing.
- 🌐 Debug third-party API failures, rate limits, inconsistent responses, and integration edge cases.
- 🧯 Focus on root causes, safe recovery, and preventing the same incident from happening again.

**My debugging workflow:**

`Observe → Reproduce → Isolate → Find Root Cause → Fix → Verify → Prevent`

### 🧠 [ContextOS](https://github.com/vivekkumar9919/ContextOS)

**Persistent context for AI-assisted development.**

A project exploring how developers can preserve and reuse relevant context while switching between AI assistants and coding tools.

- Reduce repetitive context sharing across development sessions.
- Keep project-specific information accessible to supported workflows.
- Explore local-first context management and token efficiency.

`AI Developer Tools` `Context Engineering` `Developer Productivity`

### 🔌 [MockThisAPI](https://mockthisapi.com/)

**Realistic API mocking for integration development and testing.**

Built to address a familiar backend challenge: external APIs don't always provide accessible sandboxes, and simple mocks rarely reproduce real-world failures.

- Configure endpoints, response bodies, headers, and request parameters.
- Simulate weighted HTTP status codes and randomized failures.
- Test delays, timeouts, rate limits, and pagination scenarios.

`API Design` `Backend Engineering` `Testing Infrastructure`
